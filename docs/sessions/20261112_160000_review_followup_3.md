# 코드 리뷰 및 리팩터링 3차 (2026-11-12)

`docs/sessions/20261112_143000_residual_items_done.md` 이후 전체 소스(프론트 19개 파일 +
Rust 19개 파일)를 다시 읽고 실제 동작을 기준으로 리뷰·수정했다.

## 리뷰 기준

- `.github/instructions/*.md` 와 `.github/copilot-instructions.md` 는 이 저장소에 존재하지 않는다.
  따라서 실제 적용 기준은 `AGENTS.md`(프로젝트 지식 베이스)와 `README.md`(사용자 안내 문서),
  그리고 각 언어의 표준 도구(`cargo clippy`, `cargo fmt`, `tsc`)로 삼았다.

## 1. 심각: 프론트 ↔ Rust IPC 계약 불일치 (기능 자체가 동작하지 않음)

가장 중요한 발견이다. 프론트가 호출하는 커맨드 이름/인자 키가 Rust 구현과 어긋나
**런타임에 "Command not found" / "invalid args" 로 실패**하고 있었다. 사용자에게는
"청소 버튼을 눌러도 아무 일도 일어나지 않는" 상태로 보였을 것이다.

| 위치 | 기존 | 수정 |
| --- | --- | --- |
| `src/tabs/CleanerTab.tsx` | `invoke("run_cleaner_purge", { categories })` | `invoke("clean_selected_targets", { categoryIds })` |
| `src/tabs/CleanerTab.tsx` | `invoke("clean_registry_junk", { items: 객체배열 })` | `invoke("clean_registry_junk", { itemIds: id배열 })` |
| `src/tabs/CleanerTab.tsx` | `invoke("shred_file", { path })` | `invoke("shred_file", { filePath })` |
| `src/tabs/ControlPanelTab.tsx` | `invoke("schedule_auto_shutdown", { action, minutes })` | `invoke("schedule_shutdown", { seconds, action })` |
| `src/tabs/ControlPanelTab.tsx` | `invoke("cancel_auto_shutdown")` | `invoke("cancel_shutdown")` |

### 재발 방지: IPC 계약 테스트 (`src/__tests__/ipc-contract.test.ts`)

프론트의 `invoke()` 호출을 전부 파싱해 다음을 검증한다.

1. 호출하는 커맨드 이름이 `src-tauri/src/lib.rs` 의 `generate_handler![]` 에 등록돼 있는가
2. 인자 키가 Rust 시그니처(snake_case → camelCase)와 일치하는가
3. 등록된 커맨드가 Rust 에 실제로 구현되어 있는가

검증: 인자 키를 일부러 `path` 로 되돌리면
`shred_file (src\tabs\CleanerTab.tsx): Rust(filePath, passes) vs JS(passes, path)` 로 실패한다.

## 2. 복원 지점 롤백이 사용자 파일을 옮기고 있었다

`src-tauri/src/modules/backup_manager.rs` 의 `restore_from_point` 가
`set_special_folder_path` 를 호출했는데, 이 함수는 레지스트리 값 변경 **이 아니라 실제 파일 이동**을 한다.
즉 "설정 되돌리기"를 눌러도 오늘 날짜의 파일이 예전 폴더로 옮겨졌다. 또한 경로가 같으면
`현재 경로와 동일한 경로입니다` 오류로 잡혀 "부분 롤백 실패" 라고 잘못 보고했다.

- `shell_tweaks.rs` 에 `apply_special_folder_path()` 추가: 레지스트리 값만 반영하고 파일은 건드리지 않는다.
- `backup_manager.rs` 는 이 함수를 사용한다. 이제 경로가 같아도 정상 처리된다.

## 3. 시작프로그램 비활성화가 문서화된 동작을 구현하지 않았다

`README.md` / `AGENTS.md` 는 "항목을 끄면 원본 값을 `ClickToTweakModern\DisabledStartup` 격리 키로
옮겨 보관하므로 언제든 되돌릴 수 있습니다" 라고 안내하지만, 실제 코드는 `StartupApproved` 바이트만
바꾸고 격리 저장소를 채우지 않았다. 격리 저장소 읽기/재활성화 경로가 이미 구현돼 있으나
   저장하는 쪽만 비어 있어 **항목이 격리 목록에 나타나지 않았다.**

- `startup.rs` 에 `isolate_startup_entry()` 추가: Run 값을 `위치|||명령` 형식으로 격리 저장소에
  옮기고 Run 키에서 제거한다(제거 실패 시 격리본도 되돌려 부분 반영을 막는다).
- 비활성화 시 격리 저장소로 이동, 다시 활성화하면 원래 위치로 복원된다.
- 프론트 목록에 격리 상태를 구분하는 `격리됨` 배지를 추가했다.

## 5. 경로 포함 판정 버그

`shell_tweaks.rs` 의 `is_within` 이 문자열 접두사로 경로 포함을 판정해서
`D:\ab` 를 `D:\a` 안쪽으로 오인했다(실제 이동은 안 하므로 데이터 유실은 없었으나 잘못된 거부 사유가 된다).
경로 컴포넌트 단위 대소문자 무시 비교로 교체하고 테스트를 추가했다.

## 6. 그 밖의 정확도 개선

- `shell_tweaks.rs`: `HideFileExt` 값이 없을 때 "확장자 표시" (Windows 기본값)를 기준으로 읽는다.
  기존에는 `false` 로 읽어 토글 상태가 실제와 어긋났다.
- `auto_shutdown.rs`: 60초 미만 예약이 "0분 후" 로 표시되던 문제 수정, 0초 예약(즉시 종료) 거부.
- `desktop_icons.rs`: 같은 초 안에 두 번 저장하면 스냅샷 ID 가 겹쳐 덮어쓰던 문제 → 밀리초 추가.
- `capabilities/default.json`: `core:window:allow-close` 추가. `core:default` 에는 `close` 권한이 없어
  "관리자 권한 필요" 버튼으로 재실행한 뒤 **기존 창이 닫히지 않던** 문제.

## 7. 정리

- 사용되지 않던 `tauri-plugin-opener` 플러그인/의존성 제거(프론트 호출 없음, 권한도 없음).
- 미사용 커맨드 `is_macro_running` 제거(`get_macro_status` 가 대체).
- `cargo fmt` 전체 적용 — 이전까지 `cargo fmt --check` 가 실패하는 상태였다.
- `src/tabs/WindowToolTab.tsx` 투명도 표기 "0% ~ 100%" → 실제 범위인 "10% ~ 100%".
- `tsconfig.json` 에 `types: ["node", "vite/client"]` 지정(테스트가 Node 내장 모듈을 사용).

## 남은 제약 (의도적으로 유지)

- UAC 승격, HKLM 쓰기, hosts 실제 변경, 창 투명도 조작, 매크로 입력 주입은 시스템 상태를
  바꾸므로 자동 검증하지 않았다. 코드 경로와 단위 테스트로만 검증했다.
- 포터블 EXE를 실제로 실행해 창을 확인하는 검증은 수행하지 않았다.
- `Cargo.lock` 에 `windows` 0.57/0.58/0.62 가 공존한다. 전이 의존성이라 직접 정리 대상이 아니다.
- 파일 파쇄는 저장장치/스냅샷/백업에 따라 원본이 남을 수 있다.
- 격리 저장소는 항목 이름(값 이름)을 키로 쓰므로, 서로 다른 위치의 동명 항목은 함께 격리할 수 없다.
  이 경우 오류로 알리고 기존 격리 항목을 먼저 정리하도록 안내한다.
